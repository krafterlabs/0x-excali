# 0x-excali Project Context & Instructions

Welcome! This document provides an index of the **0x-excali** desktop application context, architecture, key commands, and development conventions. Keep this updated as the project evolves.

---

## 1. Project Overview

**0x-excali** is a lightweight desktop application designed for offline-first editing of Excalidraw diagrams, with automatic synchronization to remote GitHub repositories.

### Core Tech Stack
*   **Desktop App Core:** [Wails v2 Framework](https://wails.io/) — bridges a Go backend and Web frontend via IPC bindings (no HTTP/REST server overhead).
*   **Backend Subsystems:** Go 1.25.0, SQLite Cache (`modernc.org/sqlite` — pure Go driver, WAL journal mode).
*   **Frontend UI:** React 19, TypeScript, Vite, TailwindCSS v3, [Shadcn UI](https://shadcn.com/) (using Radix primitives), `wouter` (routing).
*   **Embedded Canvas:** `@excalidraw/excalidraw` (fully style-isolated from parent app chrome).

## 2. Architecture & Service Subsystems

The application follows a decoupled layout where the frontend and backend interact entirely via Wails IPC.

### Backend Structure (`internal/`)
The Go backend is structured into five core packages. Startup wires the service dependencies and starts the async syncer:
`DB → Crypto → AuthService → Client → WorkspaceService → SyncEngine`

1.  **`database` (`internal/database/`):**
    *   **Driver:** CGO-free modern sqlite in single-connection mode (`MaxOpenConns = 1`) and WAL journal mode.
    *   **Location:** Saved locally at `os.UserConfigDir()/0x-excali/0x-excali.db`.
    *   **Crypto Subsystem (`crypto.go`):** Generates a machine-specific key using `os.Hostname()` + `os.UserHomeDir()` hash via SHA-256. Access tokens in the `auth` table are encrypted with AES-256-GCM.
    *   **Dirty-File Tracking:** `is_dirty = 1` tracks local edits that are newer than remote GitHub state, ensuring local changes survive pulls.

2.  **`github` (`internal/github/`):**
    *   **`AuthService` (`auth.go`):** Handles GitHub login using **Device Flow** (no local redirection server). Fetches profiles and manages AES-256-GCM token storage.
    *   **`Client` (`client.go`):** Authenticated REST client wrapper for `api.github.com`. Implements repository listing, trees fetching, file content reading, creation/modification (PUT), and deletion (DELETE).

3.  **`settings` (`internal/settings/`):**
    *   Persists app preferences locally in SQLite. Serializes the `Config` struct to JSON. Emits `settings:updated` Wails event to trigger immediate UI re-renders without polling.

4.  **`sync` (`internal/sync/`):**
    *   **Push-only Engine:** Drains the local SQLite `sync_queue` in batches of up to 10 items.
    *   **Commit Message Format:** `"<ISO-8601 timestamp> — <N> file(s) changed"` (batches multiple edits into a single commit).
    *   **Ordering:** Evaluated synchronously at the beginning of any `workspace.SyncFileTree()` call (push-then-pull flow).

5.  **`workspace` (`internal/workspace/`):**
    *   **Wails Bindings Entry:** Exposes workspace, folder, and file-level actions to the frontend.
    *   Handles local CRUD caching of diagrams, file-tree synchronization, folder content retrieval, and recursive deletion resolution.

### Frontend Structure (`frontend/`)
A single-page React 19 application. Key components and pages are located under `frontend/src/`:
*   **Pages:**
    *   `LoadingScreen.tsx`: Splashes during initialization.
    *   `AuthScreen.tsx`: Renders the Device Flow code and GitHub authentication link.
    *   `WorkspaceSetup.tsx`: Displays repository picking/creation flows.
    *   `Workspace.tsx`: Sidebar file navigation tree and container for the canvas.
    *   `CanvasView.tsx`: Excalidraw editor featuring 1.5s debounced auto-saves.
*   **Wails IPC Bindings:** TypeScript definitions generated by Wails are stored in `frontend/wailsjs/go/` and can be imported directly to invoke Go backend methods.

## 3. Key Commands

### Development Setup & Tooling
Ensure prerequisites (Go 1.21+, Node.js 18+, pnpm, Wails CLI) are installed.

```bash
# Set up native git pre-commit hook (runs make build on commits)
make setup

# Hot-reloading development server (HMR on Frontend, live compiles Go Backend)
make dev

# Standard build
make build

# Tidy Go modules and prune node_modules dependencies
make tidy

# Production macOS arm64 release build (obfuscated, optimized, compressed)
make production-deploy

# Clean build artifacts
make clean

# Deep clean (cleans Go caches & deletes node_modules)
make clean-all
```

### Frontend Code Quality
Ensure typescript, lint, and formatting checks pass before submitting PRs:

```bash
# Run lint checks
pnpm --dir frontend run lint

# Automatically fix lint issues
pnpm --dir frontend run lint:fix

# Format files using Prettier
pnpm --dir frontend run format

# Verify formatting
pnpm --dir frontend run format:check
```

## 4. Development Conventions

To maintain codebase cleanlines and prevent regressions, developers must adhere to the following conventions:

### Compilation & Git Hygiene
*   **Pre-commit Hook:** Every commit is validated locally by a native Git hook (`.githooks/pre-commit`) running `make build`. Never bypass this hook unless absolutely necessary.
*   **No Compiled Artifacts:** Do not commit `build/bin/` executable binaries, `frontend/dist/` build files, or `.vite/` cache artifacts.

### Pull Requests & Releases
*   **Version Bump:** If a PR constitutes a release-worthy change, modify the `.version` file to ensure the release matrix packages correctly.
*   **Review Completion:** GitHub Action `validate-pr.yml` blocks merging if any review threads remain unresolved. All threads must be explicitly resolved.
*   **Scope:** Keep pull requests targeted and focused on single feature changes or surgical fixes.

### Database & Sync Semantics
*   **CGO-Free WAL Mode:** SQLite must always be used with Single Connection (`MaxOpenConns = 1`), WAL Journal mode, and Foreign Keys active (`PRAGMA foreign_keys = ON;`). Do not introduce CGO dependencies.
*   **Name Constraints:** Empty names, names with path separators (`/`), and dot-prefixed directories or files (with the exception of internal `.gitkeep` and custom `.excalidraw-settings.json` file systems) are forbidden and blocked by filename validation rules.

### CSS & Visual Theme Styling
*   **Primary Accent Palette:** Orange is strictly reserved for primary user actions and items selection.
*   **Borders:** Borders are transparent by default across the design. Elements must explicitly opt in to borders.
*   **Excalidraw Theme Isolation:** Base app-chrome CSS resets in `index.css` use the selector `*:not(.excalidraw):not(.excalidraw *)` to guarantee that application styling does not pollute or break the styling of the embedded Excalidraw canvas.
